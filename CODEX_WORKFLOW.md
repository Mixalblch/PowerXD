# Как передать задачу Codex

1. Откройте вкладку Issues этого репозитория и нажмите New issue.
2. После слияния PR настройки выберите «Задача для Codex». До этого можно создать обычный Issue.
3. Начните заголовок с `[codex]`. Укажите: что сделать, ожидаемый результат и как проверить готовность. Одна задача — одно изменение.
4. Для черновика уберите `[codex]`; возвращение префикса означает, что задачу можно брать.

## Что произойдёт дальше

Автоматизация проверяет три репозитория раз в час. За один запуск она берёт не более одной готовой задачи от Mixalblch или pavelredwood. Обычные Issues без префикса остаются для уведомлений и ручного разбора.

Агент проверяет историю задачи, действующие инструкции проекта и существующие PR, создаёт отдельную ветку `codex/issue-N` и готовит изменения. Повторный запуск должен использовать уже созданную ветку/PR, а не дублировать работу.

Результат — pull request в этом репозитории: описание изменений, связь с Issue, выполненные проверки и известные ограничения. Работа, которая требует уточнения или недоступной среды, отмечается как заблокированная; она не считается выполненной.

Владелец проверяет PR и сливает его. Связанный Issue закрывается при слиянии, если в PR указано `Closes #N` и в репозитории включено автозакрытие.

## Проверки этого проекта

PowerXD — WPF-приложение на .NET 8 для Windows. Штатная сборка: `./build.ps1` в Windows с .NET 8 SDK; скрипт создаёт portable и self-contained EXE. На macOS/Linux не заявлять, что Windows-сборка и работа UI проверены. Если Windows runner недоступен, явно отметить это в PR и оставить задачу на проверке.

## Границы автоматического выполнения

- Обрабатываются только задачи с префиксом `[codex]` от Mixalblch или pavelredwood.
- Изменения отправляются в отдельную ветку; прямого push в main, автоматического merge, публикации релизов и production deploy нет.
- При отсутствии рабочего окружения, зависимостей или прав агент сообщает о блокере. Наличие расписания не доказывает, что сборка возможна.
- Секреты не добавляются в Issue, код или PR.
- Перед повтором заблокированной задачи добавьте уточнение или устраните блокер и оставьте комментарий `[codex retry]`.
